# ロボットと、チャンバラ。

「ロボットとチャンバラできた」を目指す展示の画面ラフです。機器なしでゲームを試すモックと、USBシリアルから剣を交えた入力を受け取る実機モードを選べます。

## 起動

Node.js 22.18以降を用意して、プロジェクト直下で実行します。

```sh
npm ci
npm run dev
```

表示先：<http://127.0.0.1:5173>

React / TypeScript / Vite / CSS。依存バージョンは `package-lock.json` に固定しています。

## 始め方

- 最初の画面で「プレイ画面」または「管理者画面」を選びます。
- 選択すると、それぞれ `#/play`、`#/admin` へ遷移します。
- プレイの準備で「ゲームテスト（モック）」または「センサ接続（実機）」を選びます。初期選択はモックです。
- モックは機器なしで、すぐに「ゲーム開始」を押せます。剣の入力はキーとボタンで再現します。
- 実機は、管理者画面の「機器の設定」でUSBシリアルポートに接続し、試しに剣を合わせて入力を確認します。その後プレイ準備で実機モードを選ぶと開始できます。ポートを開いただけでは開始できません。同じ接続中は確認済みの状態を保持するため、ゲームごとの確認は不要です。
- 接続・切断・ボーレート変更・入力確認・受信文字列の表示は管理者画面にまとめています。プレイ準備には入力方法の選択と開始可否だけを表示し、未接続・入力未確認なら管理者画面へ案内します。
- 「ゲーム開始」で `#/play/countdown` へ進み、「3・2・1」を各1秒、「スタート！」を0.6秒表示してから `#/play/game` へ自動で進みます。
- カウントダウン中に「プレイの準備に戻る」やブラウザーの戻る操作で離れると、カウントダウンを中止します。
- 実機でカウントダウン中に接続が切れた場合も、開始を中止して準備画面へ戻します。再接続後は、再び入力確認が必要です。
- カウントダウン・ゲーム画面への直リンクや再読み込みは、準備画面へ戻します。

管理者画面には「USBシリアル」と「ROS」があります。USBは選択したポートからの出力を確認し、接続先の機種は識別しません。ROSはrosbridge経由でtopicとサービスを調べられます。ROSとゲーム進行の対応付け、カメラ・物理ライトの連携はまだありません。

## USBシリアルの確認

1. PC版Chromeで <http://127.0.0.1:5173/#/admin> を開きます。Web Serial対応ブラウザーと、localhost・ループバックアドレスまたはHTTPSが必要です。
2. 機器をデータ通信対応のUSBケーブルでPCに接続し、同じポートを使う他のアプリを閉じます。
3. 接続先の機器の設定と同じボーレートを選択します。初期値は115200ですが、実機の設定を確認してください。一覧にない値は「カスタム」を選んで入力できます。
4. 「USB機器に接続」を押し、ブラウザーの選択画面で接続先のポートを選びます。
5. 「受信テキスト」に出力が表示されます。数値・CSV・JSONなどを解析せず、UTF-8の文字列として表示します。改行のない出力も表示し、受信量は生のバイト数で数えます。
6. ゲームで使う場合は試しに剣を合わせ、「ゲーム入力の確認」が確認済みになることを確かめてから「プレイの準備へ」進みます。

「ポートを開きました・未受信」は選択したシリアルポートを開けたものの、まだバイトを受け取っていない状態です。直近2秒以内にバイトを受け取ると「ポートを開きました・受信あり」、2秒以上新しいデータがなければ「ポートを開きました・2秒以上受信なし」と表示します。この接続パネルが確認するのはポートのオープンと生のバイト受信のみです。接続先の機種は識別せず、ゲームで有効な形式かどうかは別の「ゲーム入力の確認」に表示します。

自動スクロールを外すと過去の文字列を確認できます。「表示をクリア」は表示だけを消し、受信量は維持します。表示は直近65,536 UTF-16コード単位（約64,000文字）に制限し、上限を超えた場合は古い部分を省略します。ログのファイル保存はありません。

ボーレート変更時は切断してから再接続してください。アプリを開いている間は画面選択・管理者画面・プレイ画面をまたいで接続を保持します。モックへの切り替えやモックでのゲーム開始でも切断せず、モックのゲームには実機からの入力を適用しません。明示的な切断、USBの抜線、ブラウザーの再読み込み後は再接続と入力確認が必要です。再接続成功時には表示と受信量をリセットします。

文字化けする場合はボーレートと文字コード、接続できない場合は他のアプリによるポートの使用状況を確認します。

参考：[Web Serial公式ガイド](https://developer.chrome.com/docs/capabilities/serial?hl=ja)

## ROSの確認

ブラウザー側はroslibjs 2.1.0、ROS側はrosbridge WebSocketサーバーとrosapiを使います。ROS固有のtopic名・サービス名・型はアプリに固定せず、接続先から取得します。実際のROS環境での接続は未検証です。

ROSの環境を読み込み、`rosbridge_server` と `rosapi` が使える端末で起動します。標準のlaunchファイルは両方を起動します。

```sh
# ROS 2
ros2 launch rosbridge_server rosbridge_websocket_launch.xml

# ROS 1の場合はこちら
roslaunch rosbridge_server rosbridge_websocket.launch
```

1. `npm run dev` で画面を起動し、管理者画面の「ROS」を開きます。画面の起動だけではrosbridgeは起動しません。
2. 接続先URLを入力して接続します。同じPCなら `ws://localhost:9090`、別のPCなら `ws://ROS側のホスト名またはIP:9090` です。`localhost` はブラウザーを開いているPCを指します。
3. 接続するとtopic・サービスの一覧を取得します。追加・削除を反映するには一覧を更新します。
4. topicを選び、受信を開始するとJSONと受信時刻を確認できます。受信を止める操作と、表示だけを一時停止する操作を分けています。
5. サービスを選ぶと型と要求・応答の定義を取得します。要求JSONを編集し、「1回実行」で送信します。定義が取得できない場合は、サービス仕様に従ってJSONを手入力してください。

「WebSocket接続済み」は通信路を開けた状態です。topic一覧の取得や、実データの受信確認とは別です。一覧に現れる範囲はrosapi・rosbridgeの設定とROS側の環境に依存します。サービス一覧に出ても、実行を許可されているとは限りません。

topicは選んだ1つだけを購読します。bridgeに100ms間隔・待ち行列1件を指定するため、全件の記録や正確な発行頻度の計測には使えません。ROSパネルを離れると購読を停止し、WebSocket接続は維持します。戻ったら受信を開始してください。履歴と大きなJSON表示には上限があり、省略時は画面に表示します。

サービスの「応答受信」はROSから返答があったことを示します。返答中の `success` などの値や物理的な動作完了は、サービスごとの仕様で確認してください。応答待ちの間は重複送信を防ぎます。タイムアウト・切断の場合、ROS側で実行されたかは不明です。画面移動・再接続で自動再送しません。

接続URLはブラウザーに保存しますが、自動接続はしません。接続はUSB・ゲームの入力方法とは独立して保持し、明示的な切断やページ再読み込みで終了します。HTTPSで画面を開く場合は `wss://` の接続先が必要です。

一覧を取得できない場合は、`/rosapi/topics`・`/rosapi/services` が見えることを確認します。サービスの型・定義には `/rosapi/service_type`・`/rosapi/service_request_details`・`/rosapi/service_response_details` を使います。現在は標準の `/rosapi` 名前空間を前提にしています。ROS 2でtopicが見えても受信できない場合は、発行側とbridge側のQoSも確認してください。

参考：[rosbridge公式](https://github.com/RobotWebTools/rosbridge_suite) ／ [rosapiのサービス一覧](https://github.com/RobotWebTools/rosbridge_suite/blob/ros2/rosapi/README.md) ／ [roslibjs](https://github.com/RobotWebTools/roslibjs)

## 実機入力の暫定仕様

剣を交えたときに、ASCIIの `1` を1行送るものとして実装しています。区切りはLFまたはCRLFで、`1\n` / `1\r\n` を1イベントとして扱います。実機の改行方式は未確認のため、この形式は暫定です。改行のない `1` は管理者画面に表示されますが、ゲーム入力としては行が完成するまで保留します。

実機モードでは同じ `1` の入力を、受けの場面では「受け成功」、攻撃チャンス中は「命中」として扱います。命中位置は取得していないため、どのランプが点灯していても1回の命中として採用します。色の識別には未対応で、このゲーム連携は実機では未検証です。

前後の空白は取り除き、それ以外の行は無視します。分割して受信した行は復元し、256文字を超える行は次の改行まで破棄します。準備からの開始や一時停止・再開などの境界で未完の行がある場合は、その残りも改行まで破棄し、前の場面の入力を持ち越しません。

入力処理の直前に時間経過で場面が変わった場合は、その入力を採用しません。同じ受信チャンク内の残りのイベントも、新しい場面へ持ち越さないようにしています。

受信形式の解釈は `src/swordProtocol.ts` に分けています。汎用シリアル層はポートの開閉と受信だけを担当し、新着データをログ表示と入力処理へ渡します。表示ログの消去や画面移動で、過去の入力をゲームへ再送しません。

この接続で有効な `1` の行を受信したことを、実機の準備完了条件にしています。準備完了は接続中保持し、毎ゲームの再確認は求めません。機器の識別や、実際に剣が交わったかの検証は行いません。イベントがあるときだけ出力する想定なので、無受信の時間だけでは準備未完了や一時停止にしません。

## ゲームの試し方

ゲーム画面に入ると60秒の計測が始まります。左上に残り時間、右上にロボットのHP、中央に今すること、下部に赤・青・黄の3灯を表示します。残り10秒から時間を強調します。ライトの並びは実物と対応させる想定です。

モックでは、操作役が打ち合いを見て、キーまたは画面内のボタンで出来事を入力します。実機ではシリアルからの入力で受け成功と命中を判定し、受け失敗と紙風船の破損だけを手動補助として残しています。プレイ中も選択したモードを表示します。

| キー | 操作 | モード |
| --- | --- | --- |
| `Space` | 剣を受けることに成功 | モックのみ |
| `1` / `2` / `3` | 赤 / 青 / 黄の弱点を叩く | モックのみ |
| `F` | 剣を受けることに失敗 | 両方（実機では手動補助） |
| `B` | 紙風船が破損した | 両方（実機では手動補助） |
| `Esc` | 一時停止 / 再開 | 両方 |

カウントダウン後は「剣で受けて！」から始まり、この受けの場面で最初の1回の入力を受け成功にします。受けに成功すると「受けた！」を0.9秒表示し、ランダムな1灯が光って攻撃チャンスになります。命中でHPが1減り、合計3回の命中で勝利です。

モックでは点灯している色への命中だけが得点になり、暗い色への入力は得点になりません。実機では色を識別できないため、攻撃チャンス中に受信した最初の `1` を位置不明の命中として採用します。実機モードでは `Space` や色別の命中キー・ボタンは使いません。準備中・カウントダウン中・演出中・次の受けを待つ間・一時停止中・結果表示中のセンサ入力は、受け成功や命中にしません。

点灯時間は仮に8秒・6秒・4秒とし、有効な命中ごとに短くなります。命中・チャンス切れ・受け失敗の表示を0.9秒挟み、「次に備えよう」で1.5秒待つと、自動で次の「剣で受けて！」に進みます。次の打ち合いを始めるためのキーやボタンはありません。受け失敗だけでは敗北になりません。

紙風船の破損で敗北、60秒経過で時間切れです。勝敗・時間切れで進行を終了し、一時停止中は残り時間・点灯時間・演出・音を止めます。

実機モードで接続が切れると、ゲームを即座に一時停止します。「管理画面で接続を確認」から移動し、再接続と入力確認を済ませて「一時停止中のゲームに戻る」で戻ります。残り時間・HP・点灯時間・進行を保持した停止状態に戻るので、ボタンまたは `Esc` で明示的に再開します。管理画面にいる間はゲームの時間や入力を進めません。画面選択やプレイ準備へ移動した場合は、そのゲームを終了します。自動再開やモックへの自動切り替えはしません。確認のために送った入力はゲームの受け成功や命中に使いません。

BGMと合図・受け・命中の音は、自作の合成音による仮素材です。最初は音ONで、画面の音ON/OFFで切り替えられます。音楽に対するタイミング判定はまだ行いません。

敗北時（紙風船の破損）は `public/audio/lose.mp3` を1回再生します。ゲーム開始時に読み込み、音OFFでは消音、画面を離れると停止します。ファイルの読み込みに失敗した場合は仮の敗北音を使用します。音源を差し替えた場合はブラウザーを再読み込みしてください。時間切れの音は別の仮素材です。
