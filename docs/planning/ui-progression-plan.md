# UI・ゲーム進行 ラフ計画

更新日：2026-09-22  
状態：原案を人力で試すための計画

## まず試す体験

**「ロボットとチャンバラできた」と感じられるか。** 人がロボット役を演じ、画面・音・光の流れを試す。

```text
音や光の合図 → 剣を受ける
→ ロボットの剣が後退 → 3つの弱点から1つが光る
→ 点灯中に叩いて1ダメージ → 守りに戻る
```

ロボットのHPは3。3回の有効な命中で勝利、紙風船を割られたら敗北。ダメージごとに難易度を上げる。受け成功を複数回貯める方式は変更候補とする。

## 画面ラフで作るもの

- **来場者画面：** 遊び方、構え、受け、成功、弱点攻撃、命中、勝利、敗北。
- **スタッフ画面：** 開始・一時停止・リセットと、成功・失敗・命中・紙風船破損の仮入力。
- **場面プレビュー：** 画面を選んで表示の大きさや言葉を確認できるようにする。
- **合図の音：** 受け、成功、点灯、命中を区別する仮の音。

今することを大きくひとつ表示する。プレイ中は剣と実際の弱点へ視線を向けてもらい、画面は補助にする。

## 技術スタック【試作用】

React＋TypeScript＋Vite、通常のCSS、ブラウザーの音機能を使う。Reactで来場者・スタッフの表示を作り、進行の計算は小さな関数にまとめる。

まずローカルのブラウザー1画面で動かす。ROSの接続方法は相手側の環境が分かってから決め、仮入力を実際の情報へ置き換える。データベースや大きな状態管理ライブラリは初期試作では使わない。

起動方法と試せることは [アプリのREADME](../../README.md) を参照。

## 進め方

1. **画面ラフを見る。** 来場者画面の言葉・視線の誘導、スタッフの操作項目を確認する。
2. **仮ボタンで1プレイする。** ランダム点灯、HP3、勝利・敗北まで試す。
3. **剣を持って試す。** 次の行動に迷うか、音の反応が遅くないか、移動が楽しいかを観察する。
4. **実機につなぐ。** 動作や認識担当と情報を合わせ、実際の音・照明・ROS入力へ置き換える。

## 人力試作に用意するもの

- スポンジ剣2本、紙風船または守る対象の代用品。
- 左・中央・右の仮ターゲット3つ。光は操作できるライトなどで代用する。
- アプリを動かすPC、音を聞けるスピーカー。
- プレイヤー、ロボット役、アプリ操作・観察役の3人。

画面上の点灯は実際の照明を動かさない。人力試作では操作役が光る場所を合わせる。ロボット役は構えから次の構えまで約3〜4秒を目安にし、弱点への移動は数歩から試す。

## 試作中だけの仮設定

- 弱点の点灯時間は、HP3で8秒、HP2で6秒、HP1で4秒。実機の確定値ではない。
- 音楽に合わせた受けの成功判定は、まず操作役が代行する。
- 受け成功のあと、ロボット役が剣を引いて準備できたら「攻撃チャンスへ」で点灯する。
- 違う弱点や点灯時間外の命中は加点しない。1チャンスのダメージは1回だけ。
- 受け失敗・時間切れは、紙風船が無事なら同じ難易度で次へ進む。
- 判定不可は失敗にせず確認待ち。一時停止はアプリ内の進行とタイマーを止める。

## 他担当に聞くこと

3. 剣の後退、ターゲット攻撃、次の打ち合いをどう切り替えるか。
4. ターゲット命中と紙風船の破損をどう知らせるか。
