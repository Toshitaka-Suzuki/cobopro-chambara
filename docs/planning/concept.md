# ロボットと剣を交える展示：基本ルール

更新日：2026-09-22 ／ 原案反映版

「ロボットとチャンバラできた」を持ち帰る展示を目指す。発案者から共有された原案を基本案とし、これまでの追加アイデアは変更候補として扱う。

## 共有済みの前提

- ロボットはデンソーウェーブのCOBOTTA PRO。自動で動く。
- 人とロボットがスポンジ剣のようなものを持つ。人は前方の紙風船を守る。
- ロボットの速さに人が合わせる想定。構えから剣を合わせ、次の構えへ戻る1往復は約3〜4秒。
- 本人はUIとゲーム進行、別メンバーが動作・認識を担当。ROSで連携する想定。
- 剣をカメラで認識する予定。「プレイヤーの剣の認識を踏まえて動く」可能性はあるが、具体的な動作や出力は未確認。
- スタッフは説明・見守り・ゲーム全体の開始や中断を担当する案。個々の技を選んで操作する方式ではない。

## 基本ルール【原案】

1. 人の弱点は紙風船1つ。ロボットはそこを狙ってくる。
2. 音楽や光の合図に合わせ、人がロボットの剣を自分の剣で受ける。
3. タイミングよく受けることに成功すると、ロボットの剣が少し後退して隙ができる。
4. ロボット側の弱点は物理ターゲット3つ。そのうち1つがランダムに光る。
5. 人は光った弱点へ移動し、点灯中に剣で叩く。1回の有効な命中でロボットのHPが1減る。
6. ロボットの初期HPは3。合計3回の有効な命中でHP0となり、人の勝利。
7. 人の紙風船を割られたら、人の敗北。
8. ダメージを与えるごとに段階が進み、だんだん難しくなる。

「受け成功1回 → 攻撃チャンス1回 → 命中で1ダメージ」を基本とする。複数回の受け成功を貯めてダメージを増やす方式は基本案に含めない。

3回とは有効なターゲット命中の回数。失敗や時間切れも含め、打ち合いを必ず3回で打ち切る意味ではない。

## 原案と試作で調整するところ

| 項目 | 原案 | 初期試作の方針 |
| --- | --- | --- |
| リズム | 音楽や光に合わせて剣を受ける | 短い音の合図で体験を試す。判定は操作役が代行し、曲との同期と受付幅は後で調整 |
| 後ずさり | 受け成功でロボットの剣が後退 | 人がロボット役を演じる。実機の動作可否は担当者と確認 |
| 移動 | 離れた弱点まで走って叩く | 数歩の移動で試し、配置と点灯時間を調整。移動距離は確定しない |
| 難易度 | 速度アップ、受けや命中の時間を厳しくする | 3段階を試す。実機速度の上昇を前提にせず、合図・判定幅・点灯時間で調整 |
| 点灯時間 | 光っている間だけ攻撃できる | UIラフは8秒・6秒・4秒の仮値。命中できた回数で段階を進める |
| 勝敗 | 3ダメージで勝利、紙風船を割られたら敗北 | 仮ボタンで勝利・敗北まで試す。実機での破損検出は未確認 |

## 成功・失敗の扱い

来場者には「パリィ」という用語を使わず、「剣で受けて！」と伝える。

| 状況 | ゲームでの扱い |
| --- | --- |
| 合図に対応する場面で受けが成立した | 成功音と「受けた！」。動作側が攻撃チャンスへ移れることを確認してから点灯 |
| 必要な情報が揃い、受付区間が終わっても受けが成立しなかった | 攻撃チャンスなし。紙風船が無事なら次の打ち合いへ進む試作案 |
| 剣を見失う、情報不足、中断など | 判定不可。失敗・敗北にせず確認待ち |
| 点灯中の正しい弱点を叩いた | 1ダメージ、消灯。1チャンスにつき加点は1回 |
| 消灯中・違う弱点を叩いた | ダメージなし。元の受付時間を延長しない試作案 |
| 点灯中に叩かなかった | チャンス終了、HPはそのまま、同じ難易度で次へ進む試作案 |
| 紙風船を割られた | 敗北。受け失敗とは別の情報で判断する |

失敗や時間切れ後の進行は、原案を試すための仮の補完ルール。勝敗が同時に成立した場合の優先順は未決。

## 認識と自動動作で確認すること

剣を認識すること、物理的接触を検出すること、ゲーム上の成功を判定することは別に扱う。カメラの情報を動作に使えることだけでは、ゲーム用の成立判定も取得できるとは限らない。

- 1回の打ち合いと受付区間を、どの情報で識別できるか。
- カメラから何が届くか。位置・向き・接触・成立結果のどこまで取得でき、誰が判定するか。
- 剣の後退とターゲット点灯をどう連動させるか。ターゲットを叩いている間のロボット動作と、戻るタイミング。
- 紙風船の破損とターゲットの命中をどう検出するか。紙風船への接触だけで敗北とするかは確認する。
- 操作の受付と実機状態の通知、観測時刻・遅延・重複、中断や再開をどう扱うか。

必要な情報が届くまでは人力試作で代用する。ゲーム画面の切り替えだけでロボットの動作も切り替わったとは扱わない。

## UIと役割

来場者には「構えて」「剣で受けて！」「受けた！」「光ったところを叩いて！」を音・光・短い表示で伝える。HPと結果は観客にも分かるようにする。

スタッフ画面は開始・一時停止・再準備と現在の場面を中心にする。試作の仮入力は実機接続ができるまでの代用品。管理画面の一時停止と機器側の停止機能の関係は別途定義する。

## 変更候補【基本案には含めない】

複数回の受け成功をまとめてダメージにする、人からロボットの剣へ打ち込む、報酬を次へ持ち越す、試合全体に制限時間を設ける、などは体験確認後に比較する。
